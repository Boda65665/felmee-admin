# Дизайн-система Felmee Admin

Токены проекта находятся в `src/index.css`; базовые карточки, бейджи,
фильтр периода и графики переиспользуются из `src/components/`.

`TextAreaField` автоматически увеличивает высоту под содержимое и уменьшает её
после удаления текста. `rows` задаёт минимальную высоту. Поведение действует при
редактировании и просмотре, учитывает изменение ширины; внутренней прокрутки нет.

В форме салона город выбирается из населённых пунктов с FIAS/type. Поле адреса
разблокируется после выбора города и показывает только адреса внутри него.
При открытии формы сохранённый город автоматически сопоставляется с единственной
точной подсказкой (с учётом префиксов «г»/«город»), поэтому адрес можно менять
без повторного выбора города. Существующие название города, адрес и гео при этом
не меняются. Неоднозначный или отсутствующий результат требует выбора города вручную.
Изменение города очищает адрес и координаты; ручная правка адреса сбрасывает гео.
Пустой успешный ответ поиска адреса — нейтральная подсказка «Адреса не найдены»,
а не ошибка валидации. В форме салона выбор адреса при вводе поясняется нейтральным
текстом. Сохранение нового адреса всё равно требует координат выбранной подсказки.

В карточке мастера блок интерьера скрыт в просмотре и редактировании;
описание и фото интерьера остаются в карточке салона.

Меню `CategoryPicker` открывается как модальный Popover внутри профиля: это
разрешает прокрутку портального списка при активной блокировке прокрутки диалога.
Высота ограничена 280 px и доступным местом на экране; пункты не сжимаются,
названия переносятся, чекбоксы выровнены по первой строке. Множественный выбор
сохраняет меню открытым. Проверено колесом мыши на 390/1440 px с 35 категориями.

Просмотр документа запрашивает файл с `type=FULL` для PDF и изображений.
PDF отображается во встроенном просмотрщике, фото — оригиналом; доступна ссылка
«Открыть оригинал файла». Ошибка получения файла показывает сообщение и повтор,
а не бесконечную загрузку. `PREVIEW` используется для небольших изображений.
Просмотр получает `/api/file/download/{id}?type=FULL&inline=true&redirect=false`
с Bearer. Ответ может быть JSON с inline-ссылкой или бинарным фото/PDF.
Бинарный ответ показывается через локальный blob URL с очисткой при закрытии;
подписанная ссылка — напрямую без CORS fetch и без JWT к storage.
PDF занимает всю область без внутренних отступов, панели инструментов и боковых
миниатюр (`toolbar=0`, `navpanes=0`, `view=FitH`). Фото отображается через img.

## Документы

Источник: Figma `6072-8531`, `9154-9995`, `5900-6201` (обложка `6072-8948`).
`SegmentTabs variant="flat"` — прозрачная основа, активный сегмент с мягким серым
фоном, синий счётчик; прежний segmented-вариант других экранов сохранён.
Список: квадратные аватары 44 px, фиолетовые имена, единая сетка пяти колонок
без действий с глазом. Банковский статус берётся непосредственно из `bank_status`
строки списка, без дополнительных запросов карточек. Фильтр банка использует тот же `CheckboxFilterMenu` и иконку `ColumnTrigger`, что и статус заявки; можно отметить несколько банковских статусов, а «Все» отмечает/снимает все опции. Выбранные статусы объединяются по OR через скалярный `bank_status` каждого запроса, у каждого сочетания юридического типа и банковского статуса свой offset. Выбор всех статусов даёт один запрос без ограничения банка на каждый тип.
Карточка: ширина 760 px, аватар 89 px, статус банка и повтор проверки в шапке,
плоские вкладки, компактные файлы и прямоугольные кнопки. Оригинальные SVG PDF,
скачивания и повторной проверки лежат в `src/assets/document-*.svg`.
Карточка партнёра открывается по имени; просмотр файла — по его фиолетовому названию.
После принятой отправки (QUEUED) карточка сразу показывает «На проверке банком» и блокирует повторную отправку и изменение данных, даже пока сервер ещё возвращает NOT_SENT. Фактический статус в кеше берётся из API; открытая карточка обновляет его каждые 3 секунды во время ожидания и UNDER_REVIEW. Итоговый статус обновляет список и останавливает опрос; при закрытии карточки опрос также прекращается. Смена банковского статуса не сбрасывает введённые поля. Причина отказа или технической ошибки открывается нажатием на банковский статус в шапке, без автоматического попапа при открытии карточки или получении результата.

Остатки `available_rub` и `blocked_rub` показаны в целых рублях Felmee в отдельном блоке карточки; отсутствующие или небезопасные значения — «—». Суммы доступного и зарезервированного остатка не ограничивают смену типа или ИНН в интерфейсе; предупреждение об ожидании зарезервированных операций удалено по требованию владельца. Перенос `PENDING/READY/TRANSFERRING/PROCESSING/APPLYING/DONE/REVIEW_REQUIRED` показывается отдельно от проверки банка. Окончательный успех требует VERIFIED и, если был перенос, DONE. Активные фазы продолжают опрос; REVIEW_REQUIRED останавливает его, показывает код причины и ручную сверку, банковская отправка и изменение получателя недоступны. Вызовов перевода или баланса Точки из UI нет.
«Готово» недоступно без черновиков решений, при PENDING без решения или ожидании
перезагрузки. Решения по файлу разрешены только для NEW_APPLICATION/PENDING;
в остальных состояниях кнопки заблокированы и показано пояснение на русском.
При конфликте статусов во время запроса серверные ошибки переведены на русский.
Сохранение данных партнёра/реквизитов недоступно без изменений формы.
Юридический статус в карточке заявки меняется через выпадающий список. При смене отправляются все основные данные партнёра; для перехода с ООО на ИП или самозанятость показываются паспортные поля, для ООО паспортные данные не отправляются. Ограничения API по балансу, проверке заявки и дополнительным документам показываются понятными сообщениями на русском.
Для ИП и самозанятого все паспортные поля обязательны перед сохранением. Ошибки заполнения остаются у полей. Во время проверки банком форма данных партнёра заблокирована. Причина отказа банка открывается в общем попапе при открытии карточки и повторно по нажатию на статус. Неизвестные коды банка не интерпретируются; технические сбои требуют ручной повторной отправки.

## Попапы ошибок

Ошибки действий и загрузки данных во всех разделах показываются через `GlobalErrorPopup`: заголовок, понятное пояснение, исходный код API (или HTTP-статус, если кода нет) и кнопка «Понятно». `ErrorPopup` подключает ошибки локальных форм к общей очереди, `useToast().error()` использует ту же очередь. Ошибки TanStack Query показываются после завершения повторов. Одинаковые ошибки объединяются; повторная попытка после закрытия снова может показать ошибку. Ошибки загрузки сохраняют кнопки повтора, введённые данные формы не теряются. Для 429 с TTL используется отдельный попап ожидания с исходным кодом, без второго окна ошибки.

## Типы и версии документов

«Добавить документ» открывает выбор типа из требований текущего профиля и отдельный вариант «Дополнительный документ». Для типа загружается один PDF или фотография; дополнительные вложения допускают несколько файлов. Назначение всех загрузок — DOCUMENT, сохранение ожидает UPLOADED. PUT by-type передаёт expected_revision=0 для отсутствующего типа или снимок текущей revision для замены. 409 открывает пояснение; повторная запись блокируется до явного обновления карточки. Предыдущие версии доступны через историю с пагинацией и просмотром без решений; типы, переставшие применяться, также доступны в селекте истории. Дополнительные файлы отправляются через attachments и не заменяют обязательные документы.

Ответы requirements/history нормализуются на границе API из camelCase (фактическая сериализация новых backend-record) и snake_case (OpenAPI) в единый snake_case. Проверка структуры через zod отклоняет неверный ответ как invalid_response с понятным пояснением; формы не читают непроверенные массивы.

При смене юридического статуса форма запрашивает requirements с target_business_type, показывает уже одобренные документы и загрузки для needs_upload. Файлы разных типов можно загружать параллельно: имя и состояние загрузки показываются в своей строке, блокируется только её выбор файла. Эти файлы остаются черновиком и передаются только в files запроса PATCH partner. Сохранение недоступно, пока обрабатывается хотя бы один файл, без полного комплекта и до одобрения текущих документов. При смене выбранного статуса черновик очищается. Во время проверки банком добавление/замена отключены. Отмена загрузки исключает позднее прикрепление файла.

## Обзор бизнеса

Источник: Figma `3423-9316`, детали `3653-2327`, `3978-34198`, `3978-34323`.
На широком экране три KPI и три карточки метрик в один ряд; на узком — в колонку.
`KpiCard`: высота 220 px, значение 40 px, стрелка перехода с названием метрики.

`MetricChartCard`: карточка с существующими цветами `chart-gmv` и `chart-rev`,
рамкой `grey-4`, радиусом 28 px и отступами 32 px. В обзоре и деталях высота

Область диаграммы занимает остаток карточки после заголовка и легенды.

финансовые графики — в миллионах рублей. Подсказки используют единицы соответствующей оси.

Значения обзора и операций GMV пока демонстрационные; изменение периода
не подменяет их серверными данными.

## Серверные списки

Таблицы пользователей, мастеров, модерации, записей, жалоб, истории, документов,
уведомлений и партнёров, список обращений, приглашённые партнёра и комментарии
заявки используют бесконечную прокрутку вместо номеров страниц и стрелок.
`InfiniteScrollSentinel` под списком догружает данные при приближении к нижней
границе; показывает загрузку, ошибку с повтором и кнопку ручной догрузки.
При ошибке уже загруженные строки остаются на месте. Новый поиск, фильтр или
сортировка начинают новую выборку с нулевого смещения. Пустое состояние
остаётся внутри таблицы; после последней страницы дополнительного футера нет.
## Адаптация под телефоны и планшеты

`CityAutocompleteField` и `AddressAutocompleteField` используются в редактировании клиента, мастера и салона. Подсказки доступны мышью и клавишами ↑/↓/Enter; Escape закрывает список до закрытия модалки. Поля связаны с подписями и имеют семантику combobox/listbox. Во время смены запроса устаревшие подсказки не показываются. Изменение текста адреса сбрасывает выбранное гео, сохранение изменённого адреса требует выбора подсказки.

`BrandLogo` использует исходный знак SVG 44×44 и растровый wordmark из Figma, сохранённые в `src/assets/felmee-mark.svg` и `src/assets/felmee-wordmark.png`. Логотип показывается в боковом меню, мобильной шапке и форме входа. Favicon — точная копия SVG-знака в `public/favicon.svg`; заголовок вкладки — «Felmee — Админ-панель». Источник: `6089:15748`, логотип шапки `I6309:29295;6309:29274`.

Фильтры с чекбоксами допускают множественный выбор и остаются открытыми после отметки пункта и обновления результатов. Закрытие — клик снаружи, повторное нажатие триггера или Escape. Заголовки фильтров сохраняют экземпляры компонентов, а списки сохраняют предыдущие строки на время загрузки нового фильтра. Пустой результат не убирает фильтры документов и модерации. В строках жалоб участники и стрелки расположены по общей сетке. У отзыва/услуги нет пустого места под аватар: текст начинается на общей левой границе сущности, совпадающей с началом аватаров остальных объектов.

Аватары сторон жалобы используют `reporter.avatar` и `subject.avatar` через `AvatarImage`: запрос `/api/file/{id}?type=PREVIEW`, затем изображение по полученному URL. В снимках отзывов используются `author_avatar_id`, `executor_avatar_id`, `salon_avatar_id`; в услугах — `provider_avatar_id` или `salon_cover_photo_id`. Если ID или доступное изображение отсутствует, показываются инициалы.

Имена участников в жалобах открывают существующие карточки профиля поверх окна жалобы. `ProfileName` принимает явный ID и роль профиля; клиент, мастер и салон загружаются из своих API. В снимках отзывов ссылки доступны у автора, мастера и салона; в снимке услуги — у исполнителя/места приёма. После закрытия профиля сохраняются окно жалобы и его состояние. Для салона используется `salon_id`, а не ID владельца.

В чате поддержки новые сообщения сохраняют позицию чтения, если переписка прокручена вверх: появляется круглая кнопка со стрелкой вниз. Она прокручивает к последнему сообщению и скрывается; достижение конца вручную также скрывает кнопку. При открытии и чтении у нижнего края чат следует за последними сообщениями, включая изменение размеров вложений. При `prefers-reduced-motion` переход выполняется без анимации.

На ширине от 768 px длинные значения в `DataTable` обрезаются с многоточием внутри своей колонки, включая вложенные ссылки и кнопки. Составные ячейки сохраняют отдельные строки имени и подписи; кнопки действий не обрезаются. Для простых значений и имён доступен полный текст при наведении. Мобильные карточки сохраняют переносы текста.

- До 768 px строки DataTable становятся карточками с подписями полей и отдельными действиями. Метаданные `mobileLabel`, `mobileFilter`, `mobileSpan` задаются рядом с колонками. Фильтры и сортировка доступны над списком.
- На планшетах таблицы прокручиваются внутри блока с видимой полосой прокрутки.
- Боковое меню постоянно видно от 1280 px; ниже открывается модально, удерживает фокус, закрывается по Escape и возвращает фокус на кнопку меню.
- На телефонах формы переходят в одну колонку. Диалоги ограничены высотой экрана и прокручиваются внутри, кнопки действий располагаются вертикально.
- Календарь показывает один месяц до 768 px. На узких графиках сокращается число подписей. Учитывается `prefers-reduced-motion`.
- Серверные запросы и бесконечная прокрутка сохраняются.
