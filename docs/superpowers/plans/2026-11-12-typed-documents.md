# Типы и версии документов заявки

1. Синхронизировать новый контракт из backend openapi.yaml в локальный OpenAPI и сгенерировать типы. Добавить запросы требований, PUT с expected_revision и историю.
2. В документах показать тип и версию. Добавить выбор типа или дополнительных файлов. Типизированный файл заменяет текущую версию, дополнительные добавляются отдельно; дождаться UPLOADED.
3. При смене статуса запросить требования. Загрузить недостающие файлы в локальный черновик по типам и передать их только в PATCH partner. Заблокировать сохранение во время загрузки и без полного комплекта. При смене выбранного статуса сбросить черновик.
4. История — отдельный просмотр с пагинацией, без решений по старым версиям. Конфликт 409 не повторять с новой ревизией автоматически, предложить обновить карточку.
5. Проверить тестами запросы, ожидание загрузки, комплект и защиту от гонок. Проверить браузер, build и lint. Backend не перезапускать.
