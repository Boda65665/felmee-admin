## Обзор бизнеса (дашборд)

Главный экран админки: боковое меню (лого, разделы навигации, карточка
пользователя), фильтр периода, KPI-карточки, график «Оборот и выручка»
(recharts) и блок метрик «Пользователи и конверсии».

| Экран              | node-id      | Реализация                                |
| ------------------ | ------------ | ----------------------------------------- |
| Обзор бизнеса       | `3423-9316` | `src/pages/dashboard-page.tsx`            |
| Модалка «Выйти»     | `4932-10195` | `components/layout/app-shell.tsx` → `LogoutDialog` |
| Оборот (GMV) / детали | `3653-2327` | `src/pages/gmv-page.tsx`                 |
| Выручка (комиссия) / детали | `3978-34198` | `src/pages/revenue-page.tsx`         |
| Средний чек / детали | `3978-34323` | `src/pages/average-check-page.tsx` |
| Конверсия (Запись → Оплата) / детали | — (копия «Выручки») | `src/pages/conversion-page.tsx` |

Общая оболочка админ-экранов (фикс-сайдбар + модалка выхода + прокрутка) вынесена
в `components/layout/app-shell.tsx` (`AppShell`). Переиспользуемые блоки контента:
`components/dashboard/date-filter.tsx` (`DateFilter`) и
`components/dashboard/metric-chart-card.tsx` (`MetricChartCard` — карточка-график
одной метрики с переключателем линия/столбцы, используется на экранах GMV и
Выручки). Форматирование млн ₽ — `lib/format.ts` (`formatMillions`).

Переходы — через **React Router** (пути в `lib/routes.ts`): все четыре KPI-карточки
на дашборде («Оборот (GMV)», «Выручка (комиссия)», «Средний чек», «Конверсия»)
→ детальные экраны (`navigate`); пункт «Обзор бизнеса» в меню → на дашборд;
стрелка «назад» → `navigate(-1)`; выход из модалки → `/login`.

Обзор сверён с актуальными экранами справа от разделителя `4749-5411`:
три KPI (оборот, выручка, средний чек), три нижние метрики (пользователи,
отказы, записи). Снижение отказов — зелёный бейдж. Средний чек — рубли,
шкала 750–3000 ₽. На бизнес-экранах графики линейные, без переключателя типа,
высота карточки 418 px сохраняется при небольшой высоте окна. Данные демонстрационные.
«Конверсия (Запись → Оплата)» остаётся старым маршрутом, карточка перехода
с дашборда убрана: в актуальном макете её нет.

Иконки навигации — Lucide (по глифу из макета), логотип — брендовый квадрат +
текст. График — `components/ui/chart.tsx` (shadcn/recharts), данные-приближение
(значения не из макета: важны стиль и шкала).

`MetricChartCard` поддерживает два типа диаграммы через переключатель справа
сверху: линия и столбцы. Столбчатый вариант («Оборот» — фиолетовый, «Выручка» —
розовый, скруглённые верхушки) — node-id `3978-33692`. Оба типа доступны на всех
графиках: дашборд («Оборот и выручка»), GMV, Выручка, Средний чек, Конверсия.

## Управление

### Пользователи

Список пользователей: фильтр периода, 4 KPI-карточки с иконкой в цветном
квадрате (Всего / Новые за 30 дней / Активные / Заблокированные) и таблица с
поиском, сортируемыми/фильтруемыми колонками, бейджами статуса и действиями по
строке (просмотр, редактирование, блокировка / разблокировка).

| Экран        | node-id      | Реализация                  |
| ------------ | ------------ | --------------------------- |
| Пользователи | `3653-3462` | `src/pages/users-page.tsx` |

Пункт «Пользователи» в боковом меню (раздел «Управление») ведёт на `/users` и
подсвечивается на этом маршруте. Статус «Неактивен» — оранжевый: добавлены токены
`--warning` / `--warning-bg` в `src/index.css`.

### Мастера и салоны

Тот же каркас, что «Пользователи», плюс два отличия: блок-очередь «На модерации»
(3 заявки с кнопками «Одобрить» / «Отклонить с пояснением» и ссылкой «Открыть
очередь») и колонка «Роль» (пилюля Салон — зелёная, Мастер — красная). KPI:
Всего мастеров / Всего салонов / Активные (мастера/салоны) / Заблокированные;
таблица — Аккаунт / Роль / Город / Рейтинг / Отзывы / Доход / Статус / Действия.

| Экран                        | node-id      | Реализация                                            |
| ---------------------------- | ------------ | ----------------------------------------------------- |
| Мастера и салоны             | `4754-5443` | `src/pages/masters-page.tsx`                          |
| Модалка «Причина отклонения» | `4754-8153` | ↑ → `RejectReasonDialog` (по «Отклонить с пояснением») |
| Фильтр колонки «Роль»        | `4754-6315` | `CheckboxFilterMenu` (чекбоксы + Сбросить/Применить)  |
| Сортировка (Рейтинг/Отзывы/Доход) | `4754-6768` | `SortMenu` (радио По убыванию / По возрастанию)  |
| Фильтр колонки «Статус»      | `4754-7212` | `CheckboxFilterMenu`                                   |
| Фильтр колонки «Город»       | `4754-7664` | `CityFilterMenu` (поиск + список городов + футер)      |
| Очередь модерации            | `4754-8614` | `src/pages/masters-moderation-page.tsx`               |
| Модалка просмотра причины    | `4754-8605` | `RejectionReasonViewDialog` (только для «Отклонённых») |

Экран «Очередь модерации» открывается по «Открыть очередь» (`/masters/moderation`,
пункт меню «Мастера и салоны» остаётся подсвеченным — `isNavActive` матчит вложенные
пути). Три вкладки (На модерации / Одобренные / Отклонённые) показывают **одинаковый**
контент (по макету): поиск + таблица заявок (Аккаунт / Роль / Город / Ожидание /
Действия) с фильтрами роли/города, сортировкой по дате ожидания и кнопками
`ModerationActions` + просмотр. Кнопка «Отклонить» открывает тот же `RejectReasonDialog`.

Набор колонок таблицы **свой для каждой вкладки** (`GRID` / `DATE_LABEL` по вкладке):
- **На модерации** — Аккаунт / Роль / Город / Ожидание / **Действия** («2 часа назад»
  + `ModerationActions` + просмотр-глаз).
- **Одобренные** — Аккаунт / Роль / Город / **Дата одобрения** / **Менеджер** (кто
  одобрил, обычный текст). Действий/глаза нет.
- **Отклонённые** — Аккаунт / Роль / Город / **Дата отклонения** / **Менеджер**
  (с фильтром) / **Причина** (одной строкой с усечением `truncate` + инлайн-ссылка
  «читать» → модалка только для чтения `RejectionReasonViewDialog`). Действий/глаза нет.

Фильтры роль/город и сортировка по дате — на всех вкладках; фильтр по менеджеру —
только на «Отклонённых» (`MANAGER_OPTIONS` из данных).

Пункт «Мастера и салоны» ведёт на `/masters`. Цвета кнопок модерации (`#2f9e5b`
зелёная, `#e15c46` красная) — из макета, точечно inline (в палитре темы их нет).
Модалка отклонения (`RejectReasonDialog`, на shadcn `Dialog` как `LogoutDialog`):
поле причины со счётчиком `0 / 200`, «Прикрепить файл», «Отмена» / «Отправить»;
текст сбрасывается при закрытии.

Меню фильтров/сортировки колонок открываются из заголовков таблицы (`Popover`,
`src/components/ui/popover.tsx`). Компоненты — в `src/components/table-controls.tsx`
(`SortMenu`, `CheckboxFilterMenu`, `CityFilterMenu`, тип `SortDir`), чекбоксы/радио
брендовые (`#9c5cfe`). Состояние фильтров/сортировки живёт в `masters-page.tsx`;
строки таблицы реально фильтруются и сортируются (`useMemo`): доход парсится из
строки, активная иконка колонки подсвечивается брендом, пустой результат — «Ничего
не найдено». Таблица «Пользователей» пока с прежними неинтерактивными заголовками.

### Общие компоненты управления

На втором экране («Мастера и салоны») подтвердились повторяющиеся блоки — вынесены
в общий баррель `@/components` и переиспользуются обоими экранами:

- `stat-card.tsx` (`StatCard`) — KPI-карточка с иконкой в цветном квадрате
  (`tone`: brand / success / danger).
- `account-status-badge.tsx` (`AccountStatusBadge`) — пилюля статуса аккаунта
  (активен / неактивен / заблокирован).
- `row-actions.tsx` (`RowActions`) — действия строки (просмотр, редактирование,
  блокировка / «Разблокировать» по `blocked`).
- `avatar.tsx` (`Avatar`) — круглый аватар-заглушка с инициалами имени.
- `role-badge.tsx` (`RoleBadge` + тип `AccountRole`) — пилюля роли (салон/мастер).
- `moderation-actions.tsx` (`ModerationActions`) — кнопки «Одобрить» / «Отклонить
  с пояснением» (вынесены на 3-м экране — очередь модерации).
- `reject-reason-dialog.tsx` (`RejectReasonDialog`) — модалка причины отклонения.

Сами таблицы остаются в файлах экранов — колонки у экранов разные, общий «DataTable»
пока не выделяем (плоско, а не преждевременно разбито). Демо-константы (список
городов, опции роли) намеренно оставлены локальными в каждом экране.
